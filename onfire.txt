Plan de logica:

La idea es que tenemos muchos usuarios que iran registrandose y cada usuario tendra un ticket y ese ticket estara fijo con su fixed code 
y con su ticked id de 1 a 3000. Lo que ira pasando, es que por cada ticketregister que entre, esa tabla ira modificando de quien es el ticket
y si esta pago tambien o no.

Luego de saber eso,
La tabla de userticket ira modificando el ticketId y el fixed de quien es el ticket y si esta pago tambien o no.

Luego la tabla User tendra que modificar a raiz del contenido de la tabla userticket y ticket register, sus campos correspondientes.
Cuantos tickets tiene asociados, segun la tabla de ticketregister, cuantos pagos, cuantos pendientes. Cuales son esos tickets.

--- 
para las Parroquias:
Basicemante, por cada visita que se haga a una parroquia, se actualiza la tabla de visit con el userId y el parroquiaId.
En la tabla del user se actualiza el parroquiasVistitadas, en la tabla parroquia se actualiza el visits y el reward.
---
para las Preguntas:
Basicamente, por cada respuesta que se haga a una pregunta, se actualiza la tabla de respuestas con el userId y el preguntaId.
En la tabla del user se actualiza el respuestasEnviadas, en la tabla user se actualiza el respuestasCorrectas.





¡Manos a la obra! Tienes el plan y la estructura. Ahora vamos a convertir eso en **código real y desplegable**.

Como ya creaste la colección `tickets`, el resto de la base de datos la construiremos dinámicamente usando **Cloud Functions**. No necesitas crear las colecciones `ticketregister`, `userticket`, etc., manualmente; **se crearán solas** la primera vez que un usuario (o la función) guarde un dato en ellas.

### Paso 2: El Cerebro del Sistema (index.js)

Este es el código que asegura la consistencia. Ve a la carpeta `functions/` y abre el archivo `index.js`. Borra todo y pega esto:

```javascript
const functions = require("firebase-functions");
const admin = require("firebase-admin");
admin.initializeApp();

const db = admin.firestore();

// --------------------------------------------------------
// 1. LÓGICA DE TICKETS (La más crítica - Usa Transacciones)
// --------------------------------------------------------
exports.procesarTicketRegister = functions.firestore
  .document('ticketregister/{registerId}')
  .onCreate(async (snap, context) => {
    const registerData = snap.data();
    const ticketId = registerData.ticketId; // Ej: "0001"
    const userId = registerData.userId;
    const isPayed = registerData.payed; // string "yes"/"no" o boolean

    const ticketRef = db.collection('tickets').doc(ticketId);
    const userRef = db.collection('user').doc(userId);
    const newUserticketRef = db.collection('userticket').doc(); // Auto-ID

    // Ejecutamos todo como una transacción atómica (Todo o nada)
    return db.runTransaction(async (transaction) => {
      // 1. Leer el ticket maestro para obtener el código 'fixed'
      const ticketDoc = await transaction.get(ticketRef);
      if (!ticketDoc.exists) {
        throw new Error("El ticket ID no existe en la base maestra");
      }
      
      const fixedCode = ticketDoc.data().fixed;

      // 2. Actualizar la tabla maestra 'tickets'
      transaction.update(ticketRef, {
        userId: userId,
        payed: isPayed,
        updatedAt: admin.firestore.FieldValue.serverTimestamp()
      });

      // 3. Crear el registro en 'userticket'
      transaction.set(newUserticketRef, {
        userId: userId,
        ticketId: ticketId,
        fixed: fixedCode,
        payed: isPayed,
        phone: registerData.phone || "",
        email: registerData.email || "",
        timestamp: admin.firestore.FieldValue.serverTimestamp()
      });

      // 4. Actualizar contadores en 'user'
      // Nota: Leemos el usuario primero para concatenar el string de tickets
      const userDoc = await transaction.get(userRef);
      if (!userDoc.exists) {
         // Si el usuario no existe, hay que crearlo o lanzar error. 
         // Asumiremos que existe.
         throw new Error("Usuario no encontrado");
      }
      
      const userData = userDoc.data();
      let currentTicketsStr = userData['tickets-numbers'] || "";
      // Concatenar: "0001, 0005, "
      const newTicketsStr = currentTicketsStr ? `${currentTicketsStr}, ${ticketId}` : ticketId;

      // Calcular pagos
      let payedInc = isPayed === "yes" ? 1 : 0;
      let pendingInc = isPayed === "yes" ? 0 : 1;

      transaction.update(userRef, {
        "tickets-quantity": admin.firestore.FieldValue.increment(1),
        "payedtickets": admin.firestore.FieldValue.increment(payedInc),
        "pendingpay": admin.firestore.FieldValue.increment(pendingInc),
        "tickets-numbers": newTicketsStr
      });
    });
  });

// --------------------------------------------------------
// 2. LÓGICA DE PARROQUIAS Y VISITAS
// --------------------------------------------------------
exports.procesarVisita = functions.firestore
  .document('visit/{visitId}')
  .onCreate(async (snap, context) => {
    const visitData = snap.data();
    const parroquiaId = visitData.parroquiaid;
    const userId = visitData.userId;

    const parroquiaRef = db.collection('parroquia').doc(parroquiaId);
    const userRef = db.collection('user').doc(userId);

    // Obtenemos info de la parroquia para saber el reward
    const parroquiaDoc = await parroquiaRef.get();
    if (!parroquiaDoc.exists) return null;

    const reward = parroquiaDoc.data().reward || 0;
    const parroquiaName = parroquiaDoc.data().name;

    const batch = db.batch();

    // Actualizar User
    batch.update(userRef, {
      score: admin.firestore.FieldValue.increment(reward),
      // Usamos arrayUnion para no duplicar IDs, aunque tu esquema pida string, 
      // array es mejor. Si FORZOSAMENTE quieres string, habría que leer y concatenar como arriba.
      // Aquí asumo que podemos usar array para mejor práctica:
      parroquiasVistitadas: admin.firestore.FieldValue.arrayUnion(parroquiaId) 
    });

    // Actualizar Parroquia
    batch.update(parroquiaRef, {
      visits: admin.firestore.FieldValue.increment(1)
    });

    return batch.commit();
  });

// --------------------------------------------------------
// 3. LÓGICA DE PREGUNTAS Y RESPUESTAS
// --------------------------------------------------------
exports.procesarRespuesta = functions.firestore
  .document('respuesta/{respuestaId}')
  .onCreate(async (snap, context) => {
    const data = snap.data();
    const preguntaId = data.preguntaid;
    const userId = data.userId;
    const respuestaUsuario = data.respuesta;

    const preguntaRef = db.collection('pregunta').doc(preguntaId);
    const userRef = db.collection('user').doc(userId);

    const preguntaDoc = await preguntaRef.get();
    if (!preguntaDoc.exists) return null;

    const correcta = preguntaDoc.data().respuestaCorrecta;
    const esCorrecta = (respuestaUsuario === correcta);

    // Actualizamos el documento de la respuesta misma para marcar si fue correcta
    // (Opcional, pero útil para auditoría)
    await snap.ref.update({ correcta: esCorrecta });

    // Actualizamos al usuario
    const updateData = {
      respuestasEnviadas: admin.firestore.FieldValue.increment(1)
    };

    if (esCorrecta) {
      updateData.respuestasCorrectas = admin.firestore.FieldValue.increment(1);
      // Asumimos 10 puntos por correcta, o puedes leer un campo 'puntos' de la pregunta
      updateData.score = admin.firestore.FieldValue.increment(10); 
    }

    return userRef.update(updateData);
  });

```

### Paso 3: Reglas de Seguridad (firestore.rules)

Esto evita que los usuarios hackeen la app. Copia esto en tu archivo `firestore.rules`:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Helper function
    function isSignedIn() {
      return request.auth != null;
    }

    // 1. TICKETS (Maestro)
    // Solo lectura. Nadie puede escribir aquí excepto el Admin SDK (Cloud Functions)
    match /tickets/{ticketId} {
      allow read: if isSignedIn();
      allow write: if false; 
    }

    // 2. USERS
    // El usuario solo lee su propio perfil. NO puede editar su score/tickets.
    match /user/{userId} {
      allow read: if isSignedIn() && request.auth.uid == userId;
      allow write: if false; 
    }

    // 3. TICKET REGISTER (Entrada)
    // Solo permitir CREAR. No editar ni borrar.
    match /ticketregister/{docId} {
      allow create: if isSignedIn() 
                    && request.resource.data.userId == request.auth.uid; // Solo a su nombre
      allow read: if isSignedIn() && resource.data.userId == request.auth.uid;
      allow update, delete: if false;
    }

    // 4. USERTICKET
    // Solo lectura (es el resultado de la función)
    match /userticket/{docId} {
      allow read: if isSignedIn() && resource.data.userId == request.auth.uid;
      allow write: if false;
    }

    // 5. PARROQUIA (Catálogo)
    match /parroquia/{id} {
      allow read: if isSignedIn();
      allow write: if false;
    }

    // 6. VISIT
    match /visit/{id} {
      allow create: if isSignedIn() 
                    && request.resource.data.userId == request.auth.uid;
      allow read: if isSignedIn() && resource.data.userId == request.auth.uid;
    }

    // 7. PREGUNTA Y RESPUESTA
    match /pregunta/{id} {
      allow read: if isSignedIn();
      allow write: if false;
    }
    match /respuesta/{id} {
      allow create: if isSignedIn() 
                    && request.resource.data.userId == request.auth.uid;
      allow read: if isSignedIn() && resource.data.userId == request.auth.uid;
    }
  }
}

```

### ¿Qué acabas de lograr?

1. **Seguridad:** Un usuario malintencionado no puede enviarse una petición HTTP para cambiar su `score` a 9999. Si lo intenta, las reglas de Firestore lo rechazan (`allow write: if false`).
2. **Integridad:** La única forma de ganar puntos o asignar un ticket es creando un registro de "auditoría" (`ticketregister`, `visit`).
3. **Consistencia:** El código de `index.js` asegura que si asignas el ticket 0001, este quede marcado como ocupado, se asigne al usuario y se sume al contador, **todo al mismo tiempo**.
